## Question

How should the one-time migration of the four level names handle the loss of the difference between internal and confidential?

HITLD-620: five readers and five place classes (HITLD-631); model clearances by provider (HITLD-630); the label is the classification field as an object (HITLD-633).

## Options and recommendation

- A. Add a sixth reader, approved models: Readers widest to narrowest: public; any model; approved models (the owner's own account by default plus any channel granted); local model only; tools only; owner only. Migration: public to public + anywhere; internal to any model + synced store; confidential to approved models + synced store; secret is not a label (secrets are never stored and the guard refuses them); old names retired after migration
- B. Keep five readers: Map internal and confidential the same
- C. Keep the old four names beside the object: Two systems in one field

Recommended: Add a sixth reader, approved models. The chief of staff recommended it.
