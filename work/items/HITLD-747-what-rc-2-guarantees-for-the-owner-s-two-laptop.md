## Question

The owner uses hitld in a local session on a laptop for two other projects. What does covering them mean for rc.2?

Several fresh GitHub issues came from consumer projects. The owner said both projects need to be covered.

## Options and recommendation

- A. Their filed issues are in rc.2 or tracked: Every open issue from those projects maps to a tracker item and the chosen ones go into rc.2.
- B. They can install and upgrade to rc.2: The release installs with a stable hitld path, the owner install chain is done, and a project can pin rc.2.
- C. The shared UI covers their dashboards: Each project's current UI is checked against the HITLD-691 contract field list.
- D. A test run on one of them: rc.2 is run end to end on a laptop project before release.

Recommended: They can install and upgrade to rc.2. The chief of staff recommended it.
