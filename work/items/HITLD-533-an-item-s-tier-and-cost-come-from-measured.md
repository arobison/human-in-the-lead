## Question

What should decide how an item is tiered and how much it is expected to cost?

HITLD-493: dispatch routes work by a file count (dispatch.tier1_max_touches 3) and familiar yield (familiar_min_yield 0.9 over 5 samples), a size proxy the owner rejected for merging; issues 158 and 201 showed sizing ignored the plan and required reading.

## Options and recommendation

- A. Measured cost from history, with the plan as the prior: Tier and estimate come from the measured tokens of similar finished items (HITLD-438, 450), the item's own plan and required reading the starting guess until there are enough completions; file count stays only as one weak input
- B. Keep file count and yield: Predictable but sizes every item as tier 3
- C. The owner tiers each item: The owner sets the tier when promoting an item

Recommended: Measured cost from history, with the plan as the prior. The chief of staff recommended it.
