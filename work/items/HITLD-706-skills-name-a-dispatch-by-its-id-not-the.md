## Why

Since HITLD-74 (PR 393) a dispatch ID is a prefix and 16 characters, such as `D-01KAH2Q7RS4XV9TB`; a number is only a machine's display name for it. The execute and orchestrate skills still write the placeholder `D-<n>` in their commands and examples (`HITLD_DISPATCH=D-<n>`, `--dispatch D-<n>`, `Dispatch: D-<n>`, `name: D-<n>`). An agent that reads `<n>` as a counter can number its own dispatch or shorten the ID it was given, and a command with the wrong ID is refused or lands on the wrong dispatch.

## Done when

- The execute and orchestrate skills name the value `<dispatch ID>` wherever they wrote `D-<n>`, and say once that it is the ID `hitld dispatch start` and the brief give, copied whole. The execute skill's description line matches the brief's own wording ("as dispatch <ID>").
- The plugin copies of both skills are regenerated by `npm run build` and match.
- A test fails when a skill, or its plugin copy, writes `D-<n>` as a placeholder.
- `npm run check`, the offline eval gate and `hitld work check` pass.

## Notes

The brief text `hitld dispatch` writes already carries the real ID; only the skills use the placeholder. IDs from before the change (`D-1` to `D-38`) keep their meaning, and the skills may say so. Skill change: the owner's own yes to merge.
