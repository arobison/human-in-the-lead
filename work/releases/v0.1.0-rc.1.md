## Notes

- `hitld work show` and `work query` take `--json` with `api_version`; projects can declare their own fields in tracker.json; `hitld work migrate` applies tracker format migrations. (HITLD-18)
- Person and machine settings files, outside any repository, with `hitld config explain`, `config write` and `config migrate`; caps and limits take the strictest layer. (HITLD-37)
- `hitld machine detect` proposes a machine profile from local probes; items can name `resources`, and dispatch waits when this machine lacks one. (HITLD-38)
- First-run setup in the orchestrator skill; autonomous dispatch waits until the person and machine files exist (`dispatch start --by-hand` runs one named item meanwhile). (HITLD-39)
- A machine-wide registry counts live executors from every project against the person's and the machine's caps, shares usage readings per account, and locks the merge queue per repository. (HITLD-40)
- Milestones and releases are tracker entities; `hitld release propose` drafts the bump and notes from the interface delta, and `hitld release make` writes the release record and tag. (HITLD-45)
- `hitld feedback` records feedback about HITLd, with its context, in the project's private store. (HITLD-46)
- The orchestrator recognizes feedback about HITLd in the person's own turns and files a generalized version only after the person approves it. (HITLD-47)
- The commit guard refuses files above the repository's classification ceiling, at commit, at merge and in `hitld work check` (`hitld check classification`, policy `project.private_paths`). (HITLD-51)
- `hitld store export`, `import` and `sync` move the private store between machines as one encrypted file; Node 22.13 or later is required. (HITLD-60)
- Commands are tagged by the milestone that builds them; `hitld migrate` is now `hitld data migrate`; public judgements carry only what, basis and by. (HITLD-61)
- Security scanners declared in `merge.scanners` run in the merge queue against a baseline; only new, untriaged findings send a branch back (`hitld security status`, `baseline`, `verdict`, `accept`). (HITLD-63)
- `hitld rights ask` and `rights answer` work from the command line, and answered decisions are recorded in the tracker files. (HITLD-72)
- This repository's merge queue runs CodeQL 2.27.4 as its scanner, from the primary checkout; scanners get `HITLD_PRIMARY_ROOT`, so a branch cannot change the scanner that checks it. (HITLD-73)
