## Notes

- `hitld work show` and `work query` take `--json` with `api_version`; projects can declare their own fields in tracker.json; `hitld work migrate` applies tracker format migrations. (HITLD-18)
- The merge queue reruns a failing suite and compares it with the base before blaming a batch, burns in new and changed tests, and keeps a guarded quarantine file (test ID, scope, expiry, fix item); `hitld quarantine add/remove/list` and `hitld check quarantine` are new. `merge.flake_reruns` is now the rerun count. (HITLD-21)
- One digest, built from records: `hitld rights digest --trigger merge-batch|owner-writes --mark` fits one phone screen, puts questions first by cost of delay, shows only what is new, holds back in quiet hours, and returns `delivery` and `urgency`. `hitld dashboard` writes the same text to `digest.txt`. (HITLD-35)
- Person and machine settings files, outside any repository, with `hitld config explain`, `config write` and `config migrate`; caps and limits take the strictest layer. (HITLD-37)
- `hitld machine detect` proposes a machine profile from local probes; items can name `resources`, and dispatch waits when this machine lacks one. (HITLD-38)
- First-run setup in the orchestrator skill; autonomous dispatch waits until the person and machine files exist (`dispatch start --by-hand` runs one named item meanwhile). (HITLD-39)
- A machine-wide registry counts live executors from every project against the person's and the machine's caps, shares usage readings per account, and locks the merge queue per repository. (HITLD-40)
- Milestones and releases are tracker entities; `hitld release propose` drafts the bump and notes from the interface delta, and `hitld release make` writes the release record and tag. (HITLD-45)
- `hitld feedback` records feedback about HITLd, with its context, in the project's private store. (HITLD-46)
- The orchestrator recognizes feedback about HITLd in the person's own turns and files a generalized version only after the person approves it. (HITLD-47)
- The commit guard refuses files above the repository's classification ceiling, at commit, at merge and in `hitld work check` (`hitld check classification`, policy `project.private_paths`). (HITLD-51)
- `hitld store export`, `import` and `sync` move the private store between machines as one encrypted file; Node 22.13 or later is required. (HITLD-60)
- Commands are tagged by the milestone that builds them; `hitld migrate` is now `hitld data migrate` (not built yet); public judgments carry only what, basis and by. (HITLD-61)
- Security scanners declared in `merge.scanners` run in the merge queue against a baseline; only new, untriaged findings send a branch back (`hitld security status`, `baseline`, `verdict`, `accept`). (HITLD-63)
- `hitld rights ask` and `rights answer` work from the command line, and answered decisions are recorded in the tracker files. (HITLD-72)
- This repository's merge queue runs CodeQL 2.27.4 as its scanner, from the primary checkout; scanners get `HITLD_PRIMARY_ROOT`, so a branch cannot change the scanner that checks it. (HITLD-73)
- `hitld release make --branch <name>` writes the release record on a release branch for a release pull request; merging it is the release, and the release workflow tags, attests and drafts it after the owner approves the run. (HITLD-79)
- A milestone `contributions` value is any positive number in the project's value units, not only 1, 2, 3, 5, 8 or 13; scope ranks contributions by value times confidence per token. (HITLD-80)
- Consistent names: one `state` key with values proposed, planned, in-progress, done and dropped; `result` for how an attempt ended; lowercase kebab-case values; clearer names for ledger events, settings and roles. Old names are read with a warning until the next minor release; `hitld work migrate` and `hitld config migrate` rewrite files. (HITLD-82)
- Owner merge mode tests each batch before asking, shows only green branches with evidence the system computed, and takes one approval per batch (`hitld merge --all` or `--only`). `merge.owner_paths` and `merge.owner_areas` limit it, and after a run of clean merges the automatic queue is proposed. (HITLD-83)
- The person file gains `attention` keys (version 2) under owner ceilings in `policy.json`. `hitld rights pending` orders open decisions by cost of delay and gives each a delivery: now, digest, hold or default; `hitld rights sweep` applies due defaults, recorded and reversible. The person and machine files refuse a newer schema version with an upgrade message. (HITLD-84)
- `rights ask`, `rights show` and `rights answer` write `asked`, `sent` and `answered` ledger events; `hitld rights log` and `rights reverse` record and undo logged calls; `hitld rights trust` and the digest show a rubber-stamp indicator per area (`trust.rubber_stamp_seconds`). (HITLD-85)
- A chief of staff skill: the session the owner talks to, which owns scheduled tasks and starts disposable orchestrators. `hitld handover` releases the lease to a successor; `hitld run retire` and `hitld run status` are new; owner-mode merge approval is recorded with `hitld merge approve`. `orchestrator.handover_after_completions` is a new setting. (HITLD-86)
- Executors run `hitld rights who` and `hitld precedent match` before asking, and decide what the system or a precedent settles. The contract's "not your call" list now matches the seven decision rules. (HITLD-87)
- Reports, digests, calibration reviews and evals run on evidence, not the calendar: `hitld cadence due` says what is due and why, and `hitld cadence done` marks a job as run. New policy sections `reports`, `digests`, `review` and `baselines`, and `load.idle_per_core` in the machine file. (HITLD-89)
- The tracker loses two levels: a proposed project carries the shaping fields and the appetite, initiatives become milestones with no project, and milestones have one kind. `hitld work migrate` (tracker-structure) moves an existing tracker; old kinds are read with a warning. The tracker read API is version 3. (HITLD-90)
- A watchdog: `hitld dispatch watch` finds stalled or overdue dispatches from recorded progress and climbs a ladder (poke, follow-up, re-dispatch, then the owner). A quota pause records its reset time and the run resumes after it. New ledger events and `dispatch` settings; a PostToolUse hook records executor progress. (HITLD-92)
- Error codes in the hitld command's JSON are lowercase kebab-case, one code per meaning: not_permitted, not_allowed and refused (a role refusal) are not-permitted, every other snake_case code is hyphenated, and design 16.2 lists every code with its old name. hitld dashboard writes dashboard.html instead of report.html. There is no fallback for the old names. (HITLD-93)
- `hitld eval accept` writes the accepted offline baseline to `evals/baselines/` for the owner to commit, and keeps a copy in the private store. The gate reads the committed baseline first and says which it used. CI and the release workflow fail when no committed baseline matches. Accept refuses a run whose commit is not on main (`not-on-main`) or whose tree was dirty (`dirty-tree`). (HITLD-100)
- The private store's export format is version 2, encrypted to one or more age X25519 recipients (`hitld store export --recipient`). Version 1 files still import; nothing writes version 1, and `store export` no longer takes `--passphrase-fd`. (HITLD-102)
- Store devices: `hitld store device init` (keychain locally, `--cloud` for a cloud environment), `device list` and `device remove`. Which devices may open the store is the owner's decision (HITLD-113). (HITLD-103)
- `hitld store push`, `store pull`, `store status` and `store remote set/show/clear` move the encrypted store to a private git repository, whose address is kept outside the project repository (HITLD-113). Push encrypts only to the approved devices. (HITLD-105)
- `hitld run start` and `run resume` pull the store, and checkpoints, hand-overs, merges and `run retire` push; SessionStart and SessionEnd hooks pull and push. A reachable remote that will not decrypt or merge refuses the start (`store-pull-refused`); `--no-sync` skips it. A lease another machine took and never released counts as held. (HITLD-106)
- A guide, `docs/guide/store-remote.md`, sets up the private store remote: the store repository, its address, a local device, a cloud environment device, approval by the owner's answer, removal and undo. After an approval or a removal, the next push re-seals the store to the approved devices (`store status` reports `push_reason`). Offline eval scenarios cover two devices taking turns, a removed device, a discarded session, an unreleased lease and a remote with no plain text. (HITLD-107)
- `hitld run start` and `run resume` refuse when the running plugin is not the pinned release (`version-not-pinned`), before anything is pulled or recorded, and say how to fix it; a SessionStart hook reports drift. `hitld upgrade plan` lists, by role, what a pin change needs. `hitld install` turns off automatic updates for the plugin. The chief of staff upgrades only at a hand-over. (HITLD-110)
- Refusals return their documented error codes instead of `failed`; an empty `hitld work check` warns where it looked; `hitld dashboard --json --no-write` returns the data contract without writing files. (HITLD-111)
- The store remote's address is read from `HITLD_STORE_REMOTE`, the person file or a machine override, never from the project repository; `policy.json` keeps only `store.remote.required`, and a committed `store.remote.url` or device list is refused. Enrolling or removing a device is a decision only the owner answers: `hitld store device init` files a request, `hitld store device ask` asks the owner, and the approved devices are recorded inside the encrypted store. The person file is schema version 3. (HITLD-113)
- A private term list in the private store (`hitld private add/list/remove`), filled by `store remote set` and `store device init`, is checked at commit (content, paths, and a new commit-msg hook that `hitld install` adds), at merge, in `hitld work check`, and by `hitld publish check` before a pull request, comment or release note is posted; a match names its kind and place, never the term. CI checks for a committed store address, a committed device list and non-noreply email addresses. (HITLD-114)
- `hitld rights answer` refuses an answer that names no option (`answer-matches-no-option`) and records nothing; words that are exactly one option's label, allowing spelling variants, still match. A removed device's `store status` and `store device list` say it cannot open the store. Logged calls and other events written without a dispatch record the session and host. `hitld feedback publish` checks the private term list. Example device names are `example-…` placeholders. (HITLD-119)
- American English throughout: docs, skills, messages and identifiers. Renamed with no fallback: `hitld judgement weigh` and `judgement conflict` are now `hitld judgment weigh` and `judgment conflict`, their input keys `judgements` and `judgement` are `judgments` and `judgment`, the result fields `needs_judgement` and `conflicts[].judgement` are `needs_judgment` and `conflicts[].judgment`, and the eval action `judgement.weigh` is `judgment.weigh`. The `policy.json` section `judgement` is read as `judgment` with a warning for one minor release, and store device approvals written as `enrol` are read as `enroll`. `npm run check` now refuses British spellings. (HITLD-121)
- Tracker IDs come from a counter on the store repository (branch `hitld-ids`, moved with compare-and-swap) when a store remote is set, and are always checked against the remote's main and open branches, so two sessions never take the same ID (`hitld work new` reports `id_source`). Each question carries a check code; `hitld rights answer` refuses an answer whose question changed (`answer-question-changed`) and accepts `--code`. A lone letter names an option only when it is the whole answer. The merge queue and CI refuse duplicate IDs. The skills ask decisions with the harness's question tool. (HITLD-123)
- A release item carries its version in a `release` key. `hitld release propose` and `release make` find the release item for the version and treat every item or milestone it needs that is not done as a gate; `release make` refuses while any is open (`release-gates-open`), and the release workflow's record check applies the same rule. `--item` naming another version's release item is refused (`release-item-mismatch`). (HITLD-129)
